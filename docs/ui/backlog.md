## 2. 已知問題、可以再改善

- **桌面中央的船標籤會互相重疊**：船停在中央附近時明顯，手機上更擠。
- **直式手機的島很小**：桌面是橫的、螢幕是直的，受寬度限制。要明顯改善得在直式時把桌面轉 90 度（島改成上下排列），屬於較大改動，先問使用者。
- **橫式手機的桌面偏小**：螢幕太矮，上下兩條 HUD 吃掉大部分高度。
- **遠端島的角色卡**（桌機）往下翻時，會靠近中央的船標籤。
- **撕開淡出時的半透明紙張**看得到內部接縫，因為一閃而過，暫不處理。
- **兩個發起人互相應徵**時，會先播「撤回招募」再播「合作成立」，規則上正確，但觀感可能怪，看使用者意見。
- **換階段那一刻的單幀卡頓**：按下確認、手牌出現時各有 1 幀 33–67 ms（React 重繪與手牌排版）。招募結果演出本身實測順暢；之前看到「連續 1.2 秒、每幀 50 ms」的掉幀，是開發窗格被隱藏前瀏覽器降頻造成的，不是遊戲本身。量測時要確認 `document.visibilityState` 全程是 `visible`。
- **載入畫面的長度**：載入畫面（「整理港口中…」）現在會等 `scene/EffectWarmup.tsx` 的三輪預先編譯（約 62 個 shader）都連結完成才消失，編譯都藏在載入畫面後面。在隱藏窗格中量到：第 2、3 輪各在 30 ms 內送出、沒有超過 50 ms 的長影格；桌子掛上去加第一次繪製本來就會佔住主執行緒約 1 秒。還沒在可見的窗格裡看過載入畫面實際多停留多久。分頁在背景、完全不繪製時會停在載入畫面，回到前景才繼續。沉船效果也還沒在實際對局中確認。
- **疑似**：`session/usePlayback.ts` 的 `eventDelay` 是「顯示這個事件之前」的停頓，`voyage-modifiers` 的骰子動畫可能被下一個事件（`ship-resolved`，1000ms）提早截斷。沒有實際確認。
- **排版規格過時**：[`layout-spec.md`](layout-spec.md) 第 1 節寫「手機直式本版不處理」，第 2 節的區塊圖是手牌放在決策列右邊。現在已有手機版面，手牌改成置中站在操作列正上方（《殺戮尖塔》式），要更新規格。
- **殘留樣式**：`table/hudSkin.css` 還有 `.card-tip` 的規則，手牌已不用滑過顯示說明，可刪。

## 開發用預覽頁

開發伺服器（`npm run dev`）下可直接看單一演出，方便調整：

| 網址 | 內容 |
|---|---|
| `/?dev=props` | 招募道具循環播放；`&t=900` 定格在某毫秒，`&far` 遊戲距離 |
| `/?dev=pigeon` | 信鴿飛行；`&t=700` 定格，`&close` 近景，`&color=%23d0553f` 換隊色 |
| `/?dev=build` | 建築完工演出；`&asset=salvage` 換建築，`&t=1.7` 定格（秒） |
| `/?dev=models` | 資產建築模型 |
| `/?dev=sink` | 沉船與岸邊浪花 |
| `/?dev=ui-mock` | UI 風格樣張 |

手機版面：在開發窗格把視窗設成 375×812（直式）或 812×375（橫式），`data-layout` 會自動切換。
