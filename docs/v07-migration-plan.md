# 黑市商會｜V0.7 搬遷計畫（草案）

**狀態：** 草案（2026-10-12），待使用者確認第 5 節的決定後執行。
**目標：** 把正式引擎、Bot、Match Runner、連線房間與 UI 從 V0.6 換成 [`game-design.md`](game-design.md) 的 V0.7，最後部署到線上。
**依據：** 規則以 `game-design.md` 為準；`src/proto/economy`（`--preset round14`）是已模擬驗證的參考實作；架構限制見 [`architecture.md`](architecture.md)。

## 1. 原則

- **規則只看 `game-design.md`。** 原型裡為了模擬比較而存在的選項（方案 B、交易所其他效果、倉庫直售、牙行建築、角色抽牌、匿名走私等）一律不搬。
- **main 隨時保持綠燈：** 型別檢查與測試全過；搬遷期間 V0.6 的 UI 仍可在本機遊玩。
- **線上版在切換前維持 V0.6。** push 到 main 不會自動部署；V0.7 完整驗證後，挑沒人對局的時間手動部署（部署會中斷進行中的對局）。
- **遵守架構限制：** 引擎純函式、可 JSON 往返、seeded `Rng` 可重現（`architecture.md` §4.1、§4.4）；Bot 與 UI 只能看到該座位的 `PlayerView` 與私有事件（§4.3）；公開事件是可依序重播、足以重建桌面的事件流（§4.3）。

UI 的分類：

- **要刪除或重寫（V0.6 規則專屬）：** 合資招募的所有畫面與演出（`PartnerPicker`、`PartnerCard`、`recruitShow`、`RecruitFx`、`RecruitProps`、`jointBenefits`、`partnerChoice` 等）；決策區 `DecisionDock`、`TableHud`、`ConfirmChoice`；文字 `labels`、`rulesText`、`eventText`、`InfoTip`、`EventLog`、`PrivateNotes`；市場事件卡的演出 `EventShowcase`、`eventReveal`。
- **要改資料來源（3D 桌面）：** `session/board.ts`（從公開事件重建桌面）、`scene/tableModel.ts`，以及讀取這些資料的 `TableScene`、`SceneLabels`、`SeatRail`、`Islands`、`BuildSite`、`Ships`、`weather`、`dieSteps`。四棟建築的 3D 模型仍適用（V0.7 也是造船廠、航運保險、打撈公司、貿易交易所）。
- **可以沿用：** 海、天空、霧、暴風雨、風、鴿子、金幣、浪花等效果與數學；`CameraRig`；建築的零件系統；App、連線畫面、結果畫面等外殼。

## 3. 策略：以原型為基礎、平行開發、一次切換

1. 在新目錄 `src/v07/` 開發 V0.7 的引擎與 Bot（`src/v07/game`、`src/v07/bots`），以原型程式為起點正式化。此時 V0.6 的 `src/game` 與 UI 不動，main 一直能玩。
2. Match Runner、連線層與 UI 依序改接 `src/v07`。
3. 全部接好並驗證後，一次切換：`src/v07/*` 移回 `src/game`、`src/bots`，刪除 V0.6 程式與原型中只為比較而存在的選項，更新文件，部署。

不直接在 `src/game` 原地改寫，是因為 UI 有約 45 個檔案依賴它，原地改會讓 main 在 UI 搬完前無法遊玩。

## 5. 需要使用者決定

1. **搬遷方式：** 採用第 3 節的「平行開發、一次切換」？（建議）
2. **第一個可玩版本的 UI 程度：** 先求「能完整玩一局」（市場與倉庫用簡單的面板呈現），再逐步做成桌遊場景；或一開始就做完整的場景設計？建議前者，可以更早試玩、確認規則好不好玩。
3. **黑市與需求卡放在畫面哪裡：** 這是新的核心資訊，依「場景優先」的方向，可能是桌面中央的港口看板。可以在階段 5c 前再討論。
4. **V0.6 線上版：** 切換後是否還要保留 V0.6 可玩（例如另一個網址）？建議不保留，避免維護兩套。
5. **範圍外：** 2 人模式、斷線與超時規則、對局存檔，維持原本的待辦，不在這次搬遷處理。

## 6. 風險

- **UI 工作量最大**，且畫面設計（黑市、倉庫、選貨）都是新的，可能需要多輪討論。
- **私密資訊變多：** 自己的貨、選島選項、燈塔島多看的骰值；同機輪流與線上都要確認不外洩。
- **事件演出要重做：** V0.6 的演出依賴招募流程與市場事件卡，V0.7 的結算資訊更多（每艘船的貨、價格漲跌），要避免一次湧入太多資訊。
- **Bot 對真人：** 原型 Bot 有已知限制（不太敢運軍火、選島只看個性），單人對 Bot 的體驗可能需要調整。
