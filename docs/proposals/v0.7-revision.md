# 黑市商會｜V0.7 大改版提案（草案）

**狀態：** 討論中的提案，**不是規則**。本文件不是 gameplay source of truth，其中的方向、機制與任何數字都不得寫入實作或測試；每一項都必須經使用者確認並先更新 [`game-design.md`](../game-design.md) 後才能採用（見 [`AGENTS.md`](../../AGENTS.md)）。
**來源：** 2026-10-06 與使用者的討論，以及朋友試玩時的回饋「互動都集中在船骰，缺少玩家之間的互動」。
**證據：** 數據引用自 [`simulations/2026-09-28-v06-final-4p.md`](../simulations/2026-09-28-v06-final-4p.md)（2000 局，4 人，策略 Bot）。Bot 的決策方式會影響結果，數據只作方向參考。

## 1. 診斷：V0.6 的機制偏差

V0.6 的所有互動，最後都換算成「這回合某艘船的骰值 ±1」。以下是造成這種情況的結構原因。

| # | 偏差 | 現況與證據 | 後果 |
| --- | --- | --- | --- |
| D1 | **收益彼此獨立** | 每艘抵達的船收入固定（獨資 300、合資 700），與其他船的結果無關。 | 別人的船沉不沉跟我無關（打撈和交易所除外）。出航只是自己跟骰子的對賭。 |
| D2 | **海盜與護衛不對稱** | 海盜可以押別人的船沉沒並領戰利品；護衛守別人的船只能查獲走私。護衛守自己的船 4919 次，守別人的船只有 1504 次。 | 護衛只是自保手段，沒有「押別人的船抵達」的玩法。 |
| D3 | **選合資夥伴沒有差別** | 合資加成只看發起人的資產，應徵者的資產只對自己有效。 | 每個應徵者能帶來的收益都一樣，有人應徵就接受，挑選這一步形同虛設。玩家也不知道該找誰合作。 |
| D4 | **沉船和抵達一樣常見，導致資產失衡** | 獨資船抵達率 48.7%。打撈公司與貿易交易所同價（400 G），但每次收入是 60 G 對 40 G。購買次數：打撈 7975、保險 7898、造船廠 5058、交易所 2783；平均購買回合：打撈 1.25、保險 1.81。 | 打撈和保險是開局必買，交易所幾乎沒有存在感。 |
| D5 | **打不動領先者** | 海盜戰利品由銀行支付，資產完全不會被別人碰到，保險還會補償沉船。 | 攻擊領先者對他的傷害很小，落後者缺少翻盤手段。 |
| D6 | **只有船是目標，而且只活一回合** | 所有角色都只能鎖定船；損失不會延續到下一回合。 | 玩家之間沒有長期的恩怨或關係，每回合都像重新開始。 |
| D7 | **事件是環境，不是互動** | 市場事件和航海事件對所有人一視同仁。 | 事件只改變每個選項的划算程度，不會產生「針對誰」的決策。 |

V0.6 已經記錄、但尚未解決的問題：情報商人約 30～35% 偏常用（Q-06）。

### 試玩回饋：合資是理解與節奏的門檻

使用者的體感：加入合資後，遊戲開始變得難以理解，節奏也明顯變慢。

- **理解負擔：** 合資牽涉四步流程、發起人與應徵者的身分不對稱、兩層造船廠折扣、資產觸發時算一艘船、不能打撈自己持股的船、走私超額分配等規則。這些複雜度換來的選擇卻沒有意義（見 D3）。
- **節奏：** 每回合最多有 7 個決策點（`src/game/flow.ts` 的 `ROUND_SEQUENCE`）：購買資產、發起、應徵、挑選、未配對選擇、角色部署、情報重擲。其中 4 個屬於合資流程。每個決策點都要等所有決策者提交，連線時特別明顯；多數玩家在大部分合資步驟中其實沒有實質選擇。
- **改版要求：** 合資必須大幅簡化或被取代，不能再往上疊加機制。目標是每回合的決策點不超過 3 個。

## 2. 改版目標

1. **收益互相牽動**：我的收益要受到別人選擇的影響，讓猜測對手成為每個決策的核心（對應 D1、D7）。
2. **角色對稱下注**：每個角色都能對任何船押注，而且有報酬，不只是自保（對應 D2）。
3. **選夥伴要有意義**：不同的夥伴要帶來不同的價值與風險，拒絕也要是合理的選項（對應 D3）。
4. **可以翻盤，但有限度**：落後者要有追趕手段，但不能變成大家固定圍毆第一名（對應 D5）。
5. **複雜度預算**：新機制應該盡量取代舊規則，而不是疊加上去。每加入一個決策點，就要找一個可以移除或合併的地方。
6. **節奏**：每回合的決策點不超過 3 個，盡量把相關選擇合併成一次同時提交。

## 3. 提案模組

每個模組都可以做成獨立的實驗開關，分別或組合起來跑模擬。下列範例都**不含數值**，數值要由模擬決定。

### P1｜共享資金池（核心）

- **內容：** 每回合島上的資金有限，由成功抵達的船分配。建議採用混合制：一部分固定的保底收入，加上平分的資金池。
- **解決：** D1。抵達的船越少，每艘分越多，所以險惡海況下敢出航的人能賺更多。出航變成少數派賽局，擊沉對手的船也等於提高自己的收入。
- **待決定：**
  - 保底收入與資金池的比例（決定運氣成分有多重）。
  - 合資船算一份還是兩份（算一份的話合資會大幅變差）。
  - 資金池是否隨人數調整。
- **連帶修改：**
  - 走私：改為從該船分到的份額中取走。
  - 奢侈品熱潮：可改成資金池加大。
  - 皇家聯合訂單：可改成合資專用的資金池。
  - 私人貿易特許：可改成獨資專用的資金池。
- **風險：** 擊沉別人會提高自己的收入，海盜可能再度過強，戰利品可能要跟著調降。

### P2｜護航分紅（核心）

- **內容：** 護衛鎖定別人的船，如果那艘船抵達，護衛從該船的收入中分得一份。
- **解決：** D2。海盜押沉船、護衛押抵達，兩個角色對稱。搭配 P1，護航讓「別人的船抵達」從單純的損失，變成可以分一杯羹的機會。
- **待決定：**
  - 分紅來自船東的份額，還是資金池。
  - 多名護衛之間怎麼分配。
  - 船東自己的護衛是否也適用。
  - 和走私查獲之間怎麼結算。
- **替代方案：** 擊退賞金。船被海盜鎖定但仍然抵達時，海盜的部署費改付給該船的護衛。這是護衛與海盜的零和對決，但觸發頻率低。

### P3｜合資重做（核心）

> **作廢（2026-10-11）：** 使用者決定移除合資，改走 [`2026-10-economy-rework.md`](2026-10-economy-rework.md) 的方向。

- **內容：**
  - 雙方的資產都提供合資加成，同種資產不疊加。
  - 每種資產為合資帶來不同的特色，例如保險持有者當夥伴時，沉船補償的一部分分給夥伴。
- **解決：** D3。持有特定資產的玩家會成為搶手的夥伴，挑選時要在「高收益」和「低風險」之間取捨，拒絕也有了理由。這也呼應 `game-design.md` 第 2 節的目標「讓資產改變合作對象」，這個目標目前沒有做到。
- **不改規則也能做的部分：** 挑選畫面直接顯示每個應徵者能帶來的收益、持有的資產和背叛紀錄（UI）。
- **待決定：** 各資產的合資特色，以及「同種不疊加」對互相應徵的影響。

### P4｜資產襲擊（第二波）

- **內容：** 海盜可以改為鎖定某玩家的一張資產，被打中的資產本回合停擺；護衛也可以鎖定資產來防守。兩名海盜同時打同一張資產時是否直接拆除，留待模擬決定。
- **解決：** D5、D6。打得到長期資產，熱門資產自然會被壓制，部分抵銷 D4。
- **風險：** 拆除的損失太重，會讓人不敢買資產。建議先只做停擺。

### P5｜通緝令（第二波）

- **內容：** 每回合現金最多的玩家公開被懸賞。擊沉他的船（或襲擊他的資產）時有額外獎勵。
- **解決：** D5。這是自動的反領先機制，不需要玩家之間協調。
- **替代方案：** 戰利品改從受害者身上拿。這會變成零和，但可能把落後的人搶到破產。
- **風險：** 可能變成大家輪流打第一名，以及 kingmaking（落後者決定誰贏）。

### P6｜資產再平衡

- **內容：** 依 P1～P4 的結果，重新調整四種資產的價格與觸發條件。
- **注意：** P1 會改變沉船和抵達的價值，打撈和交易所的強弱也會跟著變，所以**要等核心模組確定後才調整**，避免白做工。

### 延後到 V0.8 之後

| 點子 | 延後原因 |
| --- | --- |
| 貨物系統（秘密選貨、供給過剩、貨價跨回合延續） | 會重新設計整個收益核心，份量最大。可以等 P1 的「共享收益」驗證成功後，再當成延伸。 |
| 告發走私 | 純讀人的玩法，但會多一個決策點，UI 和 Bot 都要支援。 |
| 走私者共分黑錢 | 可能和 P1 的資金池重疊，等 P1 確定後再評估。 |

## 4. 建議的整合方向

**V0.7 主題：「共享的市場」。** 以 P1＋P2＋P3 為核心，讓每個決策都牽涉到別人：

- 出航：要看別人會不會出航（P1）。
- 角色：要猜別人的船誰會被打、誰會平安（P2）。
- 合資：要挑能帶來不同價值的夥伴（P3）。

P4、P5 屬於直接衝突，等核心模組驗證後作為第二波加入。P6 最後收尾。

為了守住複雜度預算，下列項目在 P1 生效後可以考慮合併或簡化：

- 市場事件中的收入加成類事件，改成統一調整資金池。
- 貿易交易所「別人抵達時收錢」的效果，和 P2 的護航分紅功能重疊，可以重新定位。

## 5. 需要使用者決定的事

1. V0.7 的主題與範圍：是否以「共享的市場」（P1～P3）作為核心？
2. P1 的合資算份方式：一艘船一份，還是依股東人數算？
3. P2 的分紅來源：來自船東，還是來自資金池？
4. P4、P5 是否放進 V0.7，還是延到之後？
5. 貨物系統的定位：V0.8 的主軸，還是先不考慮？
6. 2 人模式（Q-05）是否一併納入這次改版的考量？

## 6. 驗證計畫

1. 在 `rules.ts` 加入預設關閉的實驗參數，正式規則維持 V0.6 不變。
2. Bot 加上「預估抵達船數」與「護航分紅期望值」等估算。
3. 以 `npm run simulate -- --summary --set ...` 比較各模組的單獨效果與組合效果，觀察下列指標：

| 指標 | 想看到的變化 |
| --- | --- |
| 護衛守別人船的比例 | 明顯上升（V0.6：1504／6423 ≈ 23%） |
| 合資比例與發起人的拒絕率 | 合資上升，拒絕不再是零 |
| 海域危險警報時的出航率 | 不再一面倒，而是穩定在某個比例 |
| 四種資產的購買分布 | 沒有開局必買的資產 |
| 海盜每次淨收益 | 維持接近打平 |
| 領先者被追上的比例 | 落後者有機會翻盤，但不是每局都被拉下來 |
| 策略勝率範圍 | 維持接近公平值（4 人 25%、3 人 33%） |

4. 模擬結果存放於 `docs/simulations/`，摘要記錄在本文件，最後由使用者決定是否採用。
