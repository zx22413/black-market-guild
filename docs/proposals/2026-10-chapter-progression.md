# 暗潮商戰｜章節式漸進解鎖（單機入門路線）提案（草稿）

**狀態：** 討論中的提案，**不是規則**。本文件不是 gameplay source of truth，其中的章節內容、解鎖順序、回合數與任何數字都只是占位的範例，不得寫入實作或測試；每一項都必須經使用者確認，涉及規則子集的部分還要先更新 [`game-design.md`](../game-design.md) 後才能採用（見 [`AGENTS.md`](../../AGENTS.md)）。
**來源：** 2026-10-27 與使用者的討論。使用者觀察到 V0.6、V0.7 給熟人試玩時「沒辦法馬上懂」，並想把遊戲往有深度的單機方向發展；單機方向的整體討論在 session「遊戲擴展方向討論」（2026-10-25），結論是「同時回合制＋roguelike 遠征」，本提案只涵蓋其中的**第一階段：入門章節**。
**證據：** 只有使用者的試玩觀察（口述、人數少、沒有紀錄），**沒有任何量化資料**。本提案的第一個目標就是補上量測。

## 1. 要解決的問題

1. **規則太多，第一次接觸無法消化。** V0.7 的規則一次包含：同時秘密提交、價格與需求卡、四種貨物（香料會壞、軍火會被沒收）、四種建築與排擠、五個角色與冷卻、通緝令、八座島、六種航海事件。
2. **現有教學是「聽講」，不是「玩」。** 見第 2 節：教學是腳本化的引導對局，固定 seed、固定骰值、玩家的選項被鎖住。學完之後第一次自由對局，才是玩家真正碰到完整規則的時候。
3. **沒有「為什麼要繼續玩」的結構。** 一個 3～4 人桌遊在沒有朋友一起玩時很難推廣；線性解鎖給單人玩家一條有目標的路，也讓遊戲能用「章節式策略賭局」這樣的類型描述自己。

## 2. 現況盤點（教學已經有什麼）

讀自 [`tutorial-outline.md`](../tutorial-outline.md)、`src/v07/tutorial`、`src/ui-v07/tutorial`：

| 項目 | 現況 |
| --- | --- |
| 形式 | host 帶領的引導對局：固定 seed、腳本化 Bot、鎖住合法行動，文字氣泡＋立繪 |
| 課程 | 基礎（3 回合）、護衛、海盜、情報商人、走私商人、軍火掩護、莊家（各 1 回合，莊家 2 回合）、開局選島 |
| 規則 | 官方數值，只縮短回合數（`shortRules(ROUNDS)`） |
| 玩家自由度 | 低：選項被 `allow` 過濾，隱藏的隨機結果由 `stage` 改寫 |
| 聚焦與提示 | `FocusMask`、`CoachCard`、`guide` 步驟已完成，且已有大量打磨 |
| 進度 | 只記「某課完成與否」，存在本機 `localStorage`（`progress.ts`） |
| 解鎖 | 無：所有課程從選單任選，角色課之間互相獨立 |

**結論：** 教學的「講解層」已經很完整，缺的是「**用受限規則真的玩一整局**」這一層，以及把課程串成一條線的**進度結構**。本提案不取代現有教學，而是疊在它上面。

## 3. 提案：章節式漸進解鎖

### 3.1 核心想法

- 一個章節 = 一場**真的對局**（玩家自由選擇、非腳本），對手是具名的 Bot，但**只開放一部分規則**。
- 每章只多開放一個新概念；過了才解鎖下一章。
- 每章開頭可以接現有的講解（`CoachCard`＋`FocusMask`）或角色單課，作為「先學再玩」。
- 最後一章是完整的 V0.7（4 人、八座島、全部角色）。

和現有教學的差異：

| | 現有教學 | 章節 |
| --- | --- | --- |
| 骰值、牌序 | 固定 | 隨機（seed 可重現） |
| 玩家選擇 | 被鎖定 | 自由，但可選項受章節規則限制 |
| Bot | 照劇本 | 真正決策的 Bot，具名 |
| 結束 | 看完示範 | 對局結算，有勝負 |

### 3.2 章節範例（暫定，順序與內容全部待確認與模擬）

| 章 | 開放的規則 | 這章要學會的事 | 對應現有講解 |
| --- | --- | --- | --- |
| 1 | 木材、鐵礦；只有投資（裝貨或不裝）；沒有角色、建築、事件 | 航行骰（3～6 抵達）、價格對需求、**擠貨會崩** | 基礎第 1～2 回合 |
| 2 | ＋建築（先開造船廠、航運保險）、香料 | 材料用來蓋還是用來裝（排擠）、香料放不住 | 基礎第 3 回合 |
| 3 | ＋護衛、海盜；通緝令 | 同時秘密部署、押注別人的船、護航費與戰利品 | 護衛、海盜課 |
| 4 | ＋情報商人；航海事件 | 資訊不對稱、事件在部署之後才公開 | 情報商人課 |
| 5 | ＋軍火、走私商人 | 沒收、掩護、走私（新手最容易搞混的一組） | 走私商人、軍火掩護課 |
| 6 | ＋莊家、其餘建築 | 預測市場本身 | 莊家課 |
| 7 | 完整 V0.7：選島、4 人 | 全部規則 | 開局選島課 |

此表只是為了討論形狀。尤其要注意：

- 「軍火」是貨物，與走私商人綁在一起；先關掉軍火，需求卡的軍火範圍要能為 0，是否可行**尚未驗證**。
- 章節是否都用 3 人（每章 2 個 Bot）還是 4 人，影響需求卡牌庫大小，**尚未決定**。

### 3.3 解鎖條件（待決，見第 6 節 Q1）

- A. 完成對局即解鎖（最寬鬆，教學導向）。
- B. 完成對局且名次不是最後。
- C. 總財富勝過該章指定的具名 Bot（最有「關卡」感，但可能卡住新手）。

### 3.4 具名對手

沿用現有 Bot 個性（`balanced`、`cautious`、`aggressive`、`opportunist`，見 `src/v07/bots/personality.ts`）和教學已有的角色名稱（`vande`、`tide` 等，見 `src/v07/tutorial/seats.ts`）。每章指定 1～2 名對手，個性逐章加強。**不做**「記仇」或跨場學習（見第 5 節）。

## 4. 技術評估（初步，尚未實作驗證）

### 4.1 可重用

- 講解層：`CoachCard`、`FocusMask`、`focus.ts`、教學腳本型別（`CoachStep`、`FocusTarget`）。
- `stage` 掛勾與 `allow` 過濾的做法（`src/v07/tutorial/stage.ts`、`allow.ts`）。
- 教學用的縮短規則做法（`shortRules`）：章節規則同樣是「官方數值，只改開放範圍與回合數」。
- 進度儲存方式（`progress.ts`）。

### 4.2 需要新做

| 項目 | 說明 | 規模 |
| --- | --- | --- |
| 章節定義 | 資料：開放的貨物、建築、角色、事件、島、人數、回合數、對手、解鎖條件、開場講解 | 中 |
| 規則子集的實現 | **這是最大的未知。** 最小侵入的做法是只在 Runner／UI 層過濾 `legalActions`（對真人與 Bot 都過濾），不動引擎；貨物與事件則可能能用 `Rules` 既有欄位（`production`、`demand` 範圍、`voyageEvents.copies`）調成 0。**是否可行要先寫一個小實驗驗證**，不可假設 | 中～大 |
| 結算與解鎖 | 章節結束畫面（名次、這章學到什麼）、判定解鎖、存進度 | 中 |
| 章節選單 | 現有 `TutorialMenu` 擴充，或新增畫面；顯示鎖定／已完成 | 小～中 |
| Bot 平衡驗證 | 每章規則子集用 `npm run simulate` 驗證沒有固定最佳解、Bot 在受限規則下不會出怪行為 | 中 |
| 匿名量測 | 章節開始、完成、放棄、在第幾回合離開（見第 5 節）。**新增執行期依賴前先向使用者確認**；先用不需依賴的做法 | 小～中 |

### 4.3 風險

- **規則子集的邊界。** 「只開放一部分角色」是否算新規則？我的判斷是它屬於教學用的對局設定（同現有 `shortRules`），不是 gameplay 規則；但這是使用者的決定，見 Q2。
- **V0.7 介面仍在調整。** 講解聚焦綁 UI 版面，版面一改就要同步修改（教學文件第 9.4 節已記錄同樣的風險）。
- **Bot 在受限規則下的行為未知。** Bot 的估值假設完整規則；關掉某些選項後它們可能變得過弱或過強。
- **進度只存在本機。** 換裝置或清除資料就歸零；暫不處理（同 `tutorial-outline.md` 第 1 節）。
- **功能凍結。** 專案目前軟凍結功能與玩法，只允許美術打磨。章節是包在規則外面的導覽層、不改規則本身，但仍算新功能，要使用者明確放行（Q3）。

## 5. 範圍外（本提案刻意不做）

- roguelike 遠征（場與場之間的升級、道具池、據點建設）：第二階段，要等第一階段的量測再決定。
- Bot 記仇、跨場學習、對手意圖提示系統。
- 世界觀、故事、主題換皮（目前仍是海盜航海皮；換皮留到最後）。
- 放置／離線生產。
- 線上多人模式的任何門檻：**不建議**把線上開房鎖在章節進度後面，只建議（不強制）新手先走過前幾章。
- 任何新的 gameplay 規則、卡牌、角色能力、數值。

## 7. 建議的進行順序（若放行）

1. **先回答 Q1～Q6**，再動手。
2. **可行性實驗：** 用一個最小腳本，在不改引擎的前提下，把第 1 章（只有投資、木材鐵礦）跑成完整對局，確認 Runner 層過濾對真人與 Bot 都有效，需求卡與價格行為正常。同時用 `npm run simulate` 檢查 Bot 在該子集的結果。
3. **原型：** 第 1、2 章加上選單、結算、進度，交給 5 名沒看過規則的人試玩，記錄他們卡在哪、是否完成。
4. **依結果決定：** 補完第 3～7 章，或調整拆法；同時再決定是否做第二階段（遠征）。

### 成功與失敗的判斷（待使用者決定門檻）

- 陌生人能否不靠任何人在旁講解，完成第 1～3 章？
- 他們在哪一章、哪一回合離開？
- 完成後是否主動再開一局？

若多數人在第 1 章就離開，問題在教學方式或遊戲本身的第一印象，而不是章節數量；那就先修第 1 章，不要擴充後面。
