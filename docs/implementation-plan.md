# 黑市商會｜規則引擎實作計畫

本文件是 MVP 規則引擎的實作計畫與進度追蹤。規則以 [`game-design.md`](game-design.md) 為準，架構以 [`architecture.md`](architecture.md) 為準；本文件只描述**怎麼做、做到哪裡**。

## 1. 範圍

**包含：**

- 完整的 3～4 人規則引擎（`src/game`）。
- Match Runner（`src/match`）。
- 隨機 Bot 與策略 Bot（`src/bots`）。
- 全 Bot 批量模擬腳本與統計報表。

**不包含：** UI、連線伺服器、2 人模式（待 `open-questions.md` Q-05）。

## 2. 模組切分

各目錄的詳細說明見該目錄的 `README.md`。

| 位置 | 職責 |
| --- | --- |
| `src/game/rules.ts` | 所有規則數值集中於此，每個數值註明對應的設計文件章節；規則邏輯不得寫死數字。 |
| `src/game/types.ts` | 玩家、船、角色、資產、事件、行動、階段等型別。 |
| `src/game/rng.ts` | seeded RNG；狀態為可序列化的整數，存於 `MatchState`。 |
| `src/game/decks.ts` | 市場事件（12 張）與航海事件（14 張）的建立、洗牌與抽牌。 |
| `src/game/flow.ts` | 狀態機：階段順序、收齊決定後的推進、自動步驟、跳過無人需決定的階段。 |
| `src/game/phases/` | M2 起，邏輯較多的階段各自拆成一個檔案。 |
| `src/game/resolution.ts` | 航行修正順序：原始骰 → 重擲 → 護衛 → 海盜 → 事件 → Clamp → 判定（M2 起）。 |
| `src/game/payouts.ts` | 收益結算的 6 個步驟（M2 起）。 |
| `src/game/scoring.ts` | 最終財富與平手判定。 |
| `src/game/view.ts` | `getPlayerView`：過濾玩家不應看到的資訊。 |
| `src/game/decisions.ts` | `getPendingDecisions` 與各決定的合法選項列舉，供 Bot、UI 與驗證共用。 |
| `src/game/engine.ts` | `createMatch`、`applyAction`：建立對局、驗證並套用行動。 |

## 3. 引擎運作方式

整局是一個狀態機。需要玩家決定的階段，收齊所有應決定座位的行動後才推進；不需要決定的步驟由引擎自動連續處理。沒有任何座位需要決定的階段會被自動跳過。

```
市場事件（自動）→ 資產購買 → 發起招募 → 應徵 → 挑選 → 未配對者選擇
→（自動：扣航運成本、擲骰）→ 角色部署 → 情報商人重擲
→（自動：航海事件、揭露角色並扣費、判定、收益）→ 下一回合；6 回合後結束
```

- `applyAction` 回傳新狀態與**公開事件紀錄**（例如「某船沉沒」「某海盜獲得戰利品」），供 UI 依序演出、重播與除錯。事件紀錄只含公開資訊；私有資訊只經由 `PlayerView` 取得。
- 行動的合法性一律以「合法選項列舉」判定，驗證與 Bot、UI 使用同一套邏輯。
- 非法行動回傳明確的錯誤（錯誤代碼＋說明），不靜默忽略。
- 所有函式不修改傳入的狀態。

## 4. 測試策略

- **規則對照測試：** 每條規則都有測試，測試名稱或註解註明 `game-design.md` 的章節。
- **組合表測試：** 修正順序等多因素規則，以表格列舉護衛、海盜、事件、Clamp 的組合逐一驗證。
- **指定骰值：** 需要特定骰值的測試，直接建立指定原始骰值的對局狀態，不依賴 seed 碰巧擲出。
- **不變量測試：** 以隨機 Bot 跑大量 seed 的完整對局，檢查：現金不為負、剛好 6 回合結束、同 seed 同行動必得相同結果、`PlayerView` 不含隱藏資訊、狀態可 JSON 往返且往返後繼續推進結果相同。
- **覆蓋率：** 目標 80% 以上（`@vitest/coverage-v8`）。

## 5. 里程碑

每個里程碑先寫測試再實作；完成後回報，由使用者決定是否 commit。

| # | 內容 | 完成時可以做到 | 狀態 |
| --- | --- | --- | --- |
| M1 | 型別、`rules.ts`、RNG 狀態、牌庫、狀態機骨架、`PlayerView`、待決定事項、最終財富與平手 | 所有人每回合都不做事也能跑完 6 回合並產生結果 | 完成 |
| M2 | 獨資與不出航、扣成本、擲骰、判定、航運收入 | 只有獨資船的完整一局 | 完成 |
| M3 | 合資招募四步驟、均分、資金限制；補上「非決定者送出行動」（`not-a-decider`）的測試 | 加入合資 | 未開始 |
| M4 | 角色部署、情報商人重擲、揭露與扣費、護衛與海盜、戰利品、走私 | 加入角色 | 未開始 |
| M5 | 資產購買、個人效果、合資加成、保險的護衛 +1、打撈與交易所上限、資產估值 | 加入資產 | 未開始 |
| M6 | 市場事件與航海事件的效果與疊加 | 規則完整 | 未開始 |
| M7 | Match Runner（含同步執行路徑）、隨機 Bot、不變量測試 | 全 Bot 對局可執行 | 未開始 |
| M8 | 策略 Bot、批量模擬腳本（`tsx`）、統計報表 | 開始回答 `open-questions.md` Q-06 | 未開始 |

M8 的報表應直接對應 `game-design.md` 第 11 節的驗證問題：獨資與合資比例、角色與資產選擇率、事件對決策的影響、勝率分布，以及已列出的疑慮（走私商人偏弱、雙護衛必定抵達、貿易交易所是否有人購買）。

## 7. 實作注意事項

- `changeCash` 在現金不足時會拋出例外（視為引擎錯誤），合法性檢查必須保證扣款前一定付得起。M3（合資出資）、M4（角色部署費）、M5（資產購買、造船廠折扣）新增扣款時，須確認「檢查付得起」與「實際扣款」之間現金不會被其他效果改變，並以測試覆蓋。

`src/match` 已納入 `tsconfig.engine.json`，與 `src/game`、`src/bots` 一樣不得使用瀏覽器或 Node API。
