# 公開上線與使用者分析｜討論草稿（2026-10-27）

**狀態：** 討論用的草稿，**不是規則來源，也不是已定案的設計**。所有「建議」都是討論中的方向，需使用者確認後才實作；牽涉規則的部分以 [`game-design.md`](../game-design.md) 為準。事件清單與數字都是占位。
**來源：** 2026-10-27 與使用者的討論。使用者沒有太多願意試玩的熟人，決定直接讓社群測試，但不確定要收集什麼回饋；討論後的方向是「先收 V0.7 的尾，開放給陌生人，並埋行為分析」，而不是先做大型單機或章節內容。
**關聯文件：** [`backlog.md`](backlog.md)（連線與部署待辦，注意它更新於 2026-10-04，部分項目可能已過時，見第 6 節）、[`../open-questions.md`](../open-questions.md) Q-09（全面公開前的開房驗證）、[`../proposals/2026-10-chapter-progression.md`](../proposals/2026-10-chapter-progression.md)（章節式入門，暫緩）、[`../proposals/2026-10-expansion-directions.md`](../proposals/2026-10-expansion-directions.md)（單機與擴展方向）。

## 1. 目標與假設

現在唯一的外部證據是使用者口述：V0.6、V0.7 給熟人看「沒辦法馬上懂」。其他關於遊戲好不好玩、陌生人會不會再玩，**都沒有資料**。因此這個階段的目標不是擴大市場，而是回答三個問題：

1. **看得懂嗎？** 陌生人在教學或前幾回合有沒有卡住、離開。
2. **玩得完嗎？** 一局有多少人打完、花多久、在哪一回合離開。
3. **想再玩嗎？** 打完後有沒有開第二局；有沒有人邀請朋友。

「獲得關注」不列為這個階段的目標；先有可以給人看的資料與口碑，才有東西可以推廣。

### 使用者的推廣假設（待驗證）

> 先讓玩家接觸單機（對 Bot）；喜歡的人會自己找朋友來玩。

這個假設帶出一條漏斗，每一段都應該能被量測（第 4 節）：

進站 → 開始單人局 → 打到第 N 回合 → 打完一局 → 開第二局 → 按邀請／開房 → 朋友加入 → 朋友打完 → 朋友回來再玩

線上房間支援 2 個真人加 Bot 補位（`online:smoke` 的做法），所以一個喜歡的玩家只需要說服**一個**朋友，不用湊滿 3～4 人。

## 2. 「可以放給陌生人」的完成條件（收尾線）

目的是替「收尾」畫終點，避免無止境打磨。達到下列條件就開放，其他（美術、音效、細節）不在這條線內。

| 條件 | 現況（需要驗證） |
| --- | --- |
| 陌生人不能亂建房或灌爆房間 | **完成**（2026-10-28）：任何人都能建房，靠 Turnstile 與頻率限制防濫用（第 5 節）；Turnstile 正式金鑰待申請 |
| 手機上能完整玩完一局 | 最近有多個手機 layout／效能修正，尚未做完整實機驗收 |
| 斷線與重連可用 | **完成**（2026-10-28）：限時、託管、暫停（`game-design.md` 第 15 節）；真手機尚未實測 |
| 有清楚的入口：單人對 Bot、免註冊 | 單人對 Bot 已存在；入口文案與落地頁未確認 |
| 匿名行為紀錄 | 未做（第 4 節） |

## 3. 入口：單人對 Bot 為主，房間為次

- 第一次來的陌生人**大概率找不到另外 2～3 個真人**，所以主要入口應是單人對 Bot。線上房間是給已經喜歡這遊戲、想找朋友的人。
- 因此分析的重心放在 Bot 對局流程，其次才是房間。

### 入口（2026-10-29 完成）

- **主選單一句話介紹：** 標題下「各懷鬼胎，讓骰子決定命運」與「單人對電腦一局約 10 分鐘・免註冊」（10 分鐘來自正式環境第一局的統計）。
- **單人局後邀請朋友：** 單機結算畫面多一顆「邀請朋友一起玩」，按下直接建一間線上房間（照常過 Turnstile），進大廳後複製連結；統計記為 `menu_pick`（`invite-after-match`）。
- **分享預覽：** `index.html` 有 Open Graph 標籤與封面 `public/og-card.jpg`（1200×630）。封面是遊戲本身的 3D 場景（`/v07.html?dev=og-card`：順風天氣、主角船揚帆駛向疊市），文案大標「誰在護航？誰在打劫？你能平安到港嗎？」、小標「各懷鬼胎，讓骰子決定命運」（使用者定稿）。重新截圖用 Chrome 無頭模式：`--headless=new --enable-unsafe-swiftshader --use-angle=swiftshader --window-size=1200,630 --virtual-time-budget=20000 --screenshot=… "http://localhost:5173/v07.html?dev=og-card"`，再用 `sips` 轉成 JPEG。

### 「新手局」暫緩

曾討論「邀請朋友時開一個對新手友善的房間」（2 真人加 Bot、回合縮短或受限規則、等待畫面的簡短說明）。結論是**暫不做**：

- 它等於把教學做成房間設定，需要同時動到房間建立、伺服器規則來源、規則子集三層，風險不低（規則子集是否可行尚未驗證，見章節提案第 4 節）。
- 在不知道陌生人是否真的會邀請朋友之前，不應預先設計入口。
- 做法改為：先讓最簡單的組合（單人對 Bot、現有房間連結、Bot 補位）被陌生人使用，用漏斗資料決定下一步。

邀請朋友的原則：**不強制**。被邀請的人不需要先通關教學才能進房（與 [`tutorial-outline.md`](../tutorial-outline.md) 第 1 節「建議、不強制」一致）。

## 4. 行為分析（2026-10-28 定案並實作）

### 4.1 要回答的問題

| 問題 | 需要的資料 |
| --- | --- |
| 看不看得懂 | 教學是否開始／完成、卡在哪一課；單人局第幾回合離開 |
| 玩不玩得完 | 開始與完成的局數、一局時間、離開時的回合與階段 |
| 想不想再玩 | 同一匿名使用者的第二局、第三局；回訪（隔天以上再來） |
| 邀不邀朋友 | 單人局後按邀請／開房的比例；房間裡第二個真人是否加入、是否打完 |
| 遊戲平衡 | 島、角色、建築的選擇與勝負（與 `docs/simulations/` 的 Bot 模擬對照） |
| 技術問題 | 連線失敗、重連次數、載入時間、裝置類型與螢幕寬度 |

### 4.2 事件清單（2026-10-28 定案）

| 分類 | 事件 | 附帶資料 |
| --- | --- | --- |
| 進站 | `visit` | 手機或電腦、是否第一次來、距離第一次來幾天、來源網域（只記網域） |
| 進站 | `menu_pick` | 在主選單點了什麼（單機、線上、教學、規則書） |
| 教學 | `tutorial_start`／`tutorial_done`／`tutorial_quit` | 哪一課；完成花幾分鐘；放棄時停在第幾步 |
| 對局 | `match_start` | 模式（單機、同機輪流、線上）、幾人局、這是他的第幾局 |
| 對局 | `round_end` | 第幾回合、自己的現金與名次 |
| 對局 | `match_end` | 名次、總財富、花幾分鐘、選的島、各角色用了幾次 |
| 對局 | `match_quit` | 中途離開時的回合與階段 |
| 對局 | `rules_open` | 規則書的哪一章、在對局中或主選單 |
| 線上 | `room_create`、`invite_copy` | （無） |
| 線上 | `room_join` | 房主或客人、是否點連結進來；房號（串起邀請與加入，房號 24 小時內就失效） |
| 線上 | `online_end` | 真人數、逾時次數、是否被託管 |
| 回饋 | `feedback` | 👍／👎、選填文字（最多 200 字） |
| 技術 | `client_error` | 錯誤的簡短訊息、在哪個畫面 |
| 技術 | `table_ready` | 3D 桌面載入秒數 |

**刻意不記：** 每個決定的細節（平衡用 Bot 模擬）、商會名稱、IP 位址、座位用的 token（重連座位的憑證，分析另用一個隨機 id）。

### 4.3 設計原則

- **匿名：** 分析用自己的隨機 id，存在 `localStorage`（讀不到就視為新使用者），和座位 token 分開。
- **不要記錄：** 主選單最底下角落一行比聲音開關更低調的註腳小字「匿名統計」，點開才看到說明與「不要記錄」開關。瀏覽器開了 Global Privacy Control 的人自動不記錄。
- **送出方式：** 瀏覽器先累積事件，每 30 秒或離開頁面時一次送出；本機開發不送。
- **伺服器端：** 只收白名單內的事件名稱與欄位，限制每批筆數、文字長度，沿用 `LimiterObject` 做每 IP 頻率限制。
- **不增加執行期依賴：** 不接第三方分析服務；儀表板的圖自己用 SVG 畫。

### 4.4 儲存與查看

**實作位置：** 事件與欄位白名單 `src/analytics/events.ts`（瀏覽器與伺服器共用）；瀏覽器端 `src/ui-v07/analytics/`（`track.ts` 佇列與開關、`useMatchAnalytics.ts` 對局、`PrivacyNote.tsx` 註腳、`FeedbackBox.tsx` 評分）；伺服器 `server/analytics.ts`（寫入）、`server/stats.ts`（儀表板資料）；資料表 `migrations/0001_events.sql`；儀表板頁 `stats.html`＋`src/stats/`。D1 資料庫 `contrabay-analytics` 已建立，資料表已套用到正式環境。

**上線前要使用者做的事：** 用 `npx wrangler secret put ADMIN_KEY` 設一把管理密碼，部署後到 `/stats` 輸入它。外部問卷建好後，把連結填進 `FeedbackBox.tsx` 的 `SURVEY_URL`。

- **儲存：** Cloudflare D1（SQL 資料庫）。免費額度每天寫入 10 萬列，初期流量遠低於此。**先不設保存期限**。
- **儀表板：** 遊戲 Worker 上的 `/stats` 頁面，打開就是最新數字；用 Worker secret `ADMIN_KEY` 保護，第一次輸入後存在瀏覽器。初版內容：漏斗（進站 → 開始對局 → 打完 → 再玩一局 → 邀請 → 朋友玩完）、每日進站（手機與電腦分開）、第一局在第幾回合離開、教學各課完成率、規則書常翻的章節、👍／👎 比例與最新留言、錯誤次數與 3D 桌面載入時間。
- **問卷：** 兩種都做，只在**打完第一局之後**的結算畫面出現：遊戲內一鍵評分（`feedback` 事件），旁邊放外部問卷連結（Google 表單，使用者建好後提供連結；沒有連結前不顯示）。

### 4.5 限制（要有心理準備）

- 使用者量很小時（可能個位數到十幾人），資料只看得出**明顯卡點**，看不出統計上的平衡差異；平衡問題仍以 Bot 模擬為主。
- 「第 2 回合離開」可能是看不懂、手機卡頓、或被打斷。數字只說明哪裡出事，不說明原因，仍需要偶爾直接問人。
- 使用者數少，不應對任何單一指標下定論。

## 5. 開放建房與防濫用（2026-10-28 完成）

使用者決定：**任何人按「建立房間」就能建房**，不需要密碼或帳號（`open-questions.md` Q-09）。防濫用的做法如下，數字都是營運用的初始值，不是遊戲規則，集中在 `server/limits.ts`，依實際流量調整。

| 措施 | 做法 | 位置 |
| --- | --- | --- |
| 機器人驗證 | 建房前跑 Cloudflare Turnstile（多數人看不到）；只檢查建房，加入房間不檢查 | `src/ui-v07/online/turnstile.ts`、`server/rooms.ts` |
| 建房頻率 | 同一 IP 每 10 分鐘最多 5 間 | `server/limits.ts`，計數在 `LimiterObject`（Durable Object） |
| 連線頻率 | 同一 IP 每分鐘最多開 30 條 WebSocket（擋猜房號與洗連線），在 Worker 就擋下、不叫醒房間 | 同上 |
| 每間房連線數 | 同時最多 8 條（4 座位加重新連線、多開分頁） | `server/rooms.ts` |
| 訊息頻率 | 每條連線每 10 秒最多 50 則，超過就斷線 | `server/rooms.ts` |
| 來源檢查 | WebSocket 只接受遊戲自己的網址（或本機開發），擋不住自寫腳本，但成本為零 | `server/limits.ts` 的 `originAllowed` |
| 房主管理 | 開局前可「移出」別人（不能再入座這間房）、「鎖房」不讓新的人入座 | `src/v07/online/room.ts` |
| 房間到期 | 沒人連線滿 1 小時、或建立滿 24 小時刪除 | `game-design.md` 第 15.3 節 |

**上線前要使用者做的事：** Turnstile 小工具已建立（2026-10-28，Managed 模式，site key 已填進 `turnstile.ts` 的 `SITE_KEY`）；還要把私密金鑰用 `npx wrangler secret put TURNSTILE_SECRET` 存成 Worker secret。兩者要一起設：只設其中一個，建房會全部失敗或完全不驗證。舊的 `HOST_KEY` secret 已經不用，可以刪掉（`npx wrangler secret delete HOST_KEY`）。

**已知限制：** 房間的禁止名單和鎖房狀態只存在記憶體，部署或房間被回收時會消失（與對局本身相同，見第 6 節）。「打完一局單人局才出現邀請朋友」的想法沒有採用，建房不設門檻。

## 9. 推廣方向（2026-10-28 討論）

使用者沒有經營粉絲專頁。結論：**不必先經營粉專**，去人已經在的地方用個人帳號發文。

| 地方 | 發什麼 |
| --- | --- |
| itch.io | 遊戲頁加網頁版連結，有自己的搜尋分類與開發日誌功能 |
| PTT BoardGame、巴哈姆特、Dcard 桌遊 | 開發心得型的文章，請大家試玩（先看版規） |
| Threads | 短影片或截圖加一兩句話，台灣獨立開發者活躍 |
| Reddit（r/WebGames、r/playmygame、r/IndieDev） | 英文，附網頁連結 |

- **素材：** 10～15 秒的短影片，拍「同時揭露角色 → 船抵達或沉沒」那一刻，比文字介紹更吸引人。
- **節奏：** 行為分析與問卷完成後才發文，第一批人才有資料。第一週先發 itch.io 加一個台灣社群；依資料修一輪，再發第二波，並把「上週多少人玩、卡在哪、改了什麼」寫成開發日誌。
- 文案、itch.io 頁面內容、短影片分鏡與截圖清單：[`../promo/launch-kit.md`](../promo/launch-kit.md)（2026-10-29）。分享的連結帶 `?src=平台`，`/stats` 的「從哪裡來」分得出各平台帶來多少人。

## 8. 不做（這個階段）

- 新手局、章節式入門、受限規則（暫緩，等漏斗資料）。
- 單機遠征、世界觀換皮、放置玩法。
- 帳號、登入、戰績、排行榜。
- 任何新的 gameplay 規則。
